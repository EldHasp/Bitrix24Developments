# Скрытые поля веса — как организовать

Семь числовых полей лида хранят вес критерия **1…4**.  
Пустое поле = критерий не участвует в среднем («Нет данных» или не заполнено).

## Зачем отдельные поля

В облачном БП/роботе удобнее считать среднее по числам, чем каждый раз разбирать enum-ID.  
Маппинг «ID списка → вес» живёт в роботах заполнения; среднее и пороги — в одном финальном роботе.

## Создание полей в Битрикс24

CRM → Лиды → Настройки → Поля → **Добавить поле**:

| Параметр | Значение |
|----------|----------|
| Тип | **Число** (не строка, не список) |
| Обязательное | нет |
| Множественное | нет |
| Показывать в фильтре / списке | по желанию **нет** (меньше шума) |

### Имена (видимые)

Единый префикс, чтобы сразу было ясно, что это служебное:

| № | Название поля | Заполняется из |
|---|---------------|----------------|
| 1 | `Служ: вес — Категория/сумма долга` | Категория/сумма долга |
| 2 | `Служ: вес — Готовность ко встрече` | Готовность ко встрече |
| 3 | `Служ: вес — Готовность внести аванс` | Готовность внести аванс |
| 4 | `Служ: вес — Платежеспособность` | Платежеспособность |
| 5 | `Служ: вес — Контактность` | Контактность |
| 6 | `Служ: вес — Статус клиента` | Статус клиента |
| 7 | `Служ: вес — Обрушающие факторы` | Обрушающие факторы |

Опционально 8-е поле: `Служ: средний вес рейтинга` (число с 2 знаками) — для отладки; в карточке сотруднику не нужно.

После создания коды будут вида `UF_CRM_…`. Зафиксировать:

```powershell
node tools/bitrix/dump-lead-rating-enums.mjs
```

и дописать коды в [`weight-fields.md`](weight-fields.md) (таблица ниже — шаблон до выгрузки).

## Как сделать «скрытыми»

Скрытость = **не показывать в карточке обычным сотрудникам**, а не «поле без прав у робота».

Практичный вариант для облака:

1. Создайте раздел карточки лида, например **«Служебное: рейтинг»**.
2. Положите туда 7 полей веса (и среднее, если есть).
3. В настройках вида карточки для ролей менеджеров этот раздел **не включайте** (или сверните и не используйте в их сценарии).
4. Для админа/настройщика раздел оставьте — удобно проверять, что робот пишет веса.

Дополнительно:

- в настройках каждого поля отключите вывод в общем списке лидов, если не нужен;
- **не** ставьте «только для чтения» для всех — робот должен уметь писать (от имени системы обычно может; если робот падает на записи — проверьте права вебхука/автоматизации).

Альтернатива без раздела: поля просто **не добавлять** ни в один видимый блок карточки менеджера — они останутся в CRM, роботы их видят, в UI почти не мешают.

## Логика заполнения (один робот на критерий или одна схема ×7)

Триггер: **изменилось** поле-список критерия.

```
если список пусто ИЛИ список == ID «Нет данных»
  → очистить соответствующее поле веса
иначе если список == ID₁ → вес = 1
иначе если список == ID₂ → вес = 2
иначе если список == ID₃ → вес = 3
иначе если список == ID₄ → вес = 4
```

ID и веса — из [`weights.md`](weights.md).

После записи веса (или отдельным роботом на изменение любого веса / любого критерия):

```
взять все непустые поля веса
avg = сумма / количество
по порогам записать «Рейтинг лида» (ID 3484/3486/3488/3490)
если ни одного веса нет → очистить «Рейтинг лида» (или не трогать — зафиксировать правило)
```

## Где хранится «таблица»

| Место | Что лежит |
|-------|-----------|
| Этот репозиторий `weights.json` | Полная таблица ID → вес / «Нет данных» |
| Роботы «список → вес» | Те же соответствия в условиях |
| 7 числовых полей | Уже посчитанные веса на конкретном лиде |
| Робот «среднее → рейтинг» | Только пороги А+/А/В/С |

Меняете значение в списке CRM → правите `weights.*` и одну ветку робота → поля веса пересчитаются при следующем изменении лида (или массовым прогоном).

## Чеклист внедрения

- [ ] Создать 7 числовых полей с префиксом `Служ: вес — …`
- [ ] Убрать их из карточки менеджера (отдельный служебный раздел / не добавлять в вид)
- [ ] Выгрузить коды `UF_CRM_*` дампом и записать в `weight-fields.md`
- [ ] 7 роботов (или 7 веток): список → вес / очистка
- [ ] 1 робот: среднее → «Рейтинг лида»
- [ ] Проверка на тестовом лиде: все «Нет данных» → рейтинг пуст; 3 критерия заполнены → среднее из трёх
