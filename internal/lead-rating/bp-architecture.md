# Архитектура БП: настройки вне веток

## Цель

Не хранить 35 соответствий «ID → вес» как дерево условий.  
**Логика БП** считает среднее; **таблица весов** лежит в настройках (глобальная константа).

Локальный `weights.json` / `bp-scoring-table.json` — чертёж и бэкап. В runtime Битрикс читает **глобальную константу**, не файл с диска.

## Что верно в предложении из AI-чата

- Вынести веса в **глобальную константу** (текст / JSON) — да.
- «Нет данных» **не включать** в таблицу → вес 0 / пусто → не увеличивать знаменатель — да.
- Менять веса без перестройки всего дерева условий — да.
- Новый критерий: дописать JSON + **один** типовой блок в цепочке (не 5 новых веток) — да.

## Что поправить относительно того текста

### 1. Ключи в JSON — не выдуманные XML_ID

У ваших значений сейчас `XML_ID` = автохеши, не `malo` / `sredne`.

**Рабочий вариант:** ключи = **ID значения списка** (как в выгрузке):

```json
"UF_CRM_1783351191840": { "3198": 1, "3200": 2, "3202": 3, "3204": 4 }
```

Готовый JSON: [`bp-scoring-table.json`](bp-scoring-table.json)  
(в нём нет ID «Нет данных» — намеренно).

Альтернатива на будущее: вручную проставить XML_ID = `1`…`4` и ключевать по XML_ID — только если в формуле БП вы реально получаете XML_ID выбранного значения (часто в документ приходит именно **ID** enum).

### 2. Функция чтения JSON на вашем портале: `jsonval`

В конструкторе формул БП есть **`jsonval`** — «Возвращает значение из JSON-строки по указанному пути».  
Это и есть нужный lookup (вместо гипотетического `JsonStringValue` из AI-чата).

Типичный вид (уточните подсказки конструктора при вставке):

```text
=jsonval({=GlobalConst:Lead_Scoring_Table}, "UF_CRM_1783352136338.3212")
```

Ожидание: вернёт `4` (вес «Готов записаться сейчас»).

Динамический путь (ID берётся из поля лида) — через склейку пути, например:

```text
=jsonval(
  {=GlobalConst:Lead_Scoring_Table},
  "UF_CRM_1783352136338." & {=Document:UF_CRM_1783352136338}
)
```

Синтаксис склейки (`&` или иной) и точное имя константы/поля — как в вашей вкладке подстановок.  
Если путь не найден («Нет данных» / пусто) — обычно пусто или ошибка → в расчёте трактовать как **0** через `mixedToNumber` / `if`.

**Первый тест:** константа + статичный путь `.3212` → должно быть `4`. Потом подключайте значение из документа.

### 3. Поле в документе

В формуле обычно подставляется значение поля списка = **ID выбранного пункта** (`3198`, …), а не человекочитаемый текст.  
Имя вида `{=Document:UF_CRM_…_ID}` зависит от конструктора — смотрите подстановку из списка полей документа.

### 4. Итог — не только среднее число

У вас «Рейтинг лида» — список **А+ / А / В / С**. После среднего нужна ещё карта порогов → enum ID.  
Черновик: [`bp-rating-thresholds.json`](bp-rating-thresholds.json).  
Её тоже лучше держать константой (или 4 условия только на пороги — это уже мало и стабильно).

### 5. Скрытые поля веса

При работающем JSON-lookup **не обязательны**.  
Можно сразу копить `Summa_Ballov` / `Active_Lists_Count` в переменных БП.  
Служебные числовые поля — опционально для отладки «что посчитал робот».

## Целевая схема (с `jsonval`)

1. Глобальная константа `Lead_Scoring_Table` (Текст) = содержимое [`bp-scoring-table.json`](bp-scoring-table.json) (одна строка или компактный JSON без лишних переносов, если конструктор капризничает).
2. Переменные БП: `Summa_Ballov`, `Active_Lists_Count`, `Current_Weight`, `Avg_Score`.
3. Для каждого из 7 критериев — блок «Изменение переменных»:
   - `Current_Weight` = `mixedToNumber(jsonval(…, "UF_…. " & Document:UF_…))` или 0;
   - `Active_Lists_Count` += 1 если вес > 0;
   - `Summa_Ballov` += вес.
4. `Avg_Score` = сумма / счётчик (если счётчик > 0).
5. Записать «Рейтинг лида» по порогам.

## Актуальный runtime (своё активити БП) — прод с 2026-07

На портале расчёт **не** через `jsonval` в БП.  
Сервис [`apps/lead-rating-api/`](../../apps/lead-rating-api/README.md):

1. Локальное приложение + активити **«Расчёт рейтинга лида»** (`bizproc.event.send`).
2. OAuth (`BITRIX_CLIENT_ID`/`SECRET` + save-auth) + **отдельный** `BITRIX_WEBHOOK_URL` в Layero (запас после деплоев).
3. Автозапуск БП на create/update; `crm.lead.update` рейтинга только если значение изменилось.
4. HTTP API `POST /v1/lead-rating/calculate` — запасной путь.

Чертёж весов: `bp-scoring-table.json` / `weights.md`; в runtime их читает API из `apps/lead-rating-api/data/`.  
Подробные грабли: [`docs/bitrix-local-app-activity.md`](../../docs/bitrix-local-app-activity.md).
